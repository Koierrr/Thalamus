# 她的记忆系统设计 v3（2026-09-13）

> 这篇讲**她怎么记事、怎么忘事**——只讲模型与规则，不讲代码。
> 代码锚点、迁移细节与验证数字见《工程实施档案（减法轮 + 加法轮 E1–E4）》；这里回答"为什么这样设计"。

## 一、双层引擎

- **主力：记忆引擎（mem0）** —— 向量存在本机、算向量的模型也在本机（bge-m3），**只有"把对话整理成记忆"那一步用云端的便宜模型**。它在后台以一个独立小服务运行（端口 43122）。
  三个已知要点：查记忆时必须指定"是谁的记忆"；向量的维度必须和算向量的模型一致（bge-m3 是 1024 维）；服务出错后靠"文件更新时间"自动恢复，不用手动重启。
- **兜底：本地 JSON**（`memory.json`）写穿镜像 —— 每条写入都同步落一份 JSON；引擎挂了自动降级、一条不丢；迁移幂等（按用户 + 文本去重）。
- **写失败必须可见**：降级时会记一笔（几条没进引擎、最近一次什么时候、什么原因），后台「记忆」页顶部红字标出来 —— 不许静默降级。

## 二、记忆属于谁（归属轴 `cat`）

每条记忆有且只有一个归属：

| 归属 | 装什么 | 例子 |
|---|---|---|
| **我**（关于他的事） | 他提过的事实、偏好、日程 | 他不吃香菜；他下周三要去成都出差 |
| **她**（她自己的话与成长） | 她自己的表态、她的变化 | 我打算下周去杭州；今天想通了一件事 |
| **世界**（她生活里的流水与社交圈） | 世界引擎每晚写的日常 | （生活）午饭后刷到大理洱海的骑行视频 |

**判定只有一处**：先看正文前缀 ——「（生活）」= 世界、「（成长）」= 她；再看是不是她自己的自述；其余算"我"。
后台「记忆」页可以按归属筛选，也可以改归属。

## 三、会不会被忘（桶轴 `bucket`）

**归属管"是谁的事"，桶管"会不会被忘"** —— 两个轴，互不干扰。这是 v3 新增的一层。

| 桶 | 什么进这个桶 | 怎么随时间变淡 |
|---|---|---|
| **会淡忘** | 普通的事、世界引擎写的流水 | 21 天左右半衰 |
| **固化** | 你手写的、女娲种子、你手动点「固化」的 | **不衰减，一直记得** |
| **她自己的感受** | 她自己的话、她的成长 | 60 天左右半衰（比普通事慢得多） |

**遗忘曲线的三条规则**：

1. **只降权，永不删**。淡忘不等于删除——很久没提过的事会被排到后面，但它还在，搜得到。
2. **权重有地板**（0.25）。再久也不会降到 0——她不会"完全忘了你"。
3. **被真正想起才刷新**。"最近被想起的时间"只在她这一轮真的把这条记忆用进回复时更新（6 小时内不重复记），而不是"被检索到就算"。

后台「记忆」页能看到：共几条 · 会淡忘几条 · 固化几条 · 感受几条 · **很久没提过几条**；每一条都能就地改桶。

> 为什么原来那套（重要度 1-5 星 + 标签 + 置顶）被砍掉：它和"会不会被忘"是两套并存的评价体系，而且**重要度和标签实际上没有任何读取点**（写了没人用）。现在只剩"桶"一个旋钮，判定也只有一处。

## 四、双向记忆（她不只记得你说什么，也记得自己说过什么）

- **抽取**：她在回复里的表态句（我要 / 我打算 / 我决定 / 我准备 / 我约了 / 我答应 / 我会 / 我更喜欢 / 我讨厌 / 我最怕 / 我想去 / 我想学…）会被单独归档为**归属=她、桶=她自己的感受**。
- **检索**：引擎路径与本地路径**都有**"她自己的话"这一路——曾经漏掉过，结果就是"她想不起自己说过的话"。
- **注入**：提示词里分成两段——【你记得的关于对方/最近的事】与【你自己说过的话（立场与生活线，务必一致、可自然延续）】。
- **开关与可见**：后台「记忆」页的「双向记忆」卡 = 开关 + 她自己的话列表（与主列表同一份数据，可看可搜可改可删）。

## 五、检索与打分

- 每轮回复检索 topK 条（可调）+ 本地兜底，**两者取其一、不合并**（防重复）。提炼（把对话整理成记忆）的频率可调，省 token。
- **打分 = 遗忘权重 × 相关性**。相关性 = 关键词命中 + 向量相似度；**引擎本来就会返回相似度，以前被丢掉了，现在用上了**。固化过的条目如果相关性低，名额没满时会保底补进来（不让"你固化过的"被挤掉）。
- **情绪滤镜**：心情差的时候，想起的事会带上刺（同一条记忆，注入的语气不同）。
- **语言互染**：他常说的词和梗，她学进去用。
- **主人画像**：世界引擎每晚结合聊天重写"她对你的印象"，注入提示词。

## 六、长对话不会断片

聊天记录超过一定轮数时，**不再直接砍掉最老的那段**，而是先把它**总结成一条记忆**（进她的记忆系统，以后检索得到），提示词里用「你们之前聊过的（这是你自己记得的）」代替。

**关键规则：摘要还没生成好之前，绝不裁** —— 宁可提示词长一点，也不让她断片。

## 七、性格演化数据

`evolution.json` 计数器（被哄 / 被怼 / 聊过多少，只统计主人的互动）；世界引擎每满 7 天结算一次，微调六维（合计 ≤ ±5，八维基准钳制 ±25）并写一条成长理由（进"世界"归属）；结算后清零盖章。账本在「她 → 她的成长」里可见。

## 八、她把什么发出去了（隐私边界）

| 通道 | 发什么 | 现状 |
|---|---|---|
| **遥测** | 匿名运行信息（**不含记忆正文**） | **已四层关闭**（配置层关不掉，只能从进程环境层关） |
| **提炼模型**（云端） | 每次整理记忆时，把刚聊的那段对话原文发出去（大约他的 1500 字 + 她的 1000 字） | **保留在云端**（用户裁决；后台界面已写明） |
| **向量服务** | 记忆正文 → 用来算向量 | **留本机**（Ollama）；若改成云端，界面会提示"每条记忆正文都会发出去" |

## 九、管理与迁移

- 后台「记忆」页：引擎状态 / 双向记忆 / 她记得的事（搜索 · 按归属与桶筛选 · 按时间或"还想得起来"排序 · 20 条一页 · 就地改桶 · 导出 Markdown）/ 提炼设置（顺位链 + 模式 + 条数 + 轮数 + 一键重置）。
- **迁移**：旧格式的记忆元数据会自动升级（判桶 + 补回引擎 id + 损坏条目单独列出来等你处置），可重复执行不会重复写。损坏的条目**不自动删、不自动进桶**。
