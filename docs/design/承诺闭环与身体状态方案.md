# 第一节 A8 承诺闭环（抽取 + 到期队列 + 到期主动提）

一句话方案：每轮回复发出后，用便宜模型把「她答应过、且能落到具体日子」的话抽成一条承诺，写进独立的 promises.json 队列；现有 60 秒心跳里加一个 promises.tick()，到期当天由 soul.proactive 新增的 promise 种类主动发一条提起；她当时在睡觉就推到起床后 15~45 分钟；后台「你们」页新增「她答应过的事」列表，可取消、可改期、可手动再提；抽错或她反悔，下一轮抽取时把待兑现清单一并交给模型比对，明确反悔的自动取消。

## ① 现状与证据

1.1 她的口头承诺现在没有任何东西接住。全链路只有三处可能"沾到"承诺，全部止步于记忆文本：

- soul.js recordConversation（约 1228 行）的双向记忆自述正则（约 1264 行）：

      const SELF_RE = /(我要|我打算|我决定|我准备|我下周|我明天|我后天|我最近|我约了|我答应|我会|我更喜欢|我不喜欢|我讨厌|我最怕|我想去|我想学)/;

  命中后只调 addMemory 存一句她的话（source:self），没有到期时间、没有触发器。

- 本地兜底抽取的提示词（约 1296 行 / 1304 行，同一段提示词两处复制）允许模型返回 todo 字段：

      "todo":{"due":"YYYY-MM-DD","text":"待办内容"}或null

  随后 addMemory（约 1313 行）把它存进记忆条目。

- 这个 todo 字段是死字段。_jsonAdd（约 593 行）写入 `todo: item.todo || null`，但全仓检索 todo/todos 的读取点为零：getMemories（约 568~577 行）只规整 `todos` 数组形状防崩（约 576 行 `todos: Array.isArray(raw.todos) ? raw.todos : []`），index.js 约 2650 行重置时也只保持 `{entries:[],todos:[]}` 形状。没有任何代码读条目上的 todo，更没有按 due 触发的逻辑。mem0 主路径（/extract，python/memory_service.py 约 409 行起）连 todo 都不产出。

  结论：到期提醒这件事在存储形状上留了个洞（todos 数组 + 条目 todo 字段），在行为上完全缺失。方案不复活这个死字段做半吊子修补（那会变成"两个源都写到期能力"），而是立一个唯一权威队列，死字段的处置交给记忆桶化方案（docs/design/记忆桶化方案.md）统一砍。

1.2 到期触发的现成载体：心跳已经存在，且链路已改成事件驱动 + 冷却。

- index.js 约 424 行：`this._lifeTimer = setInterval(() => { void this._lifeTick(); }, 60000);`——每 60 秒一跳，这就是唯一的定时骨架，不需要第二个定时器。
- index.js _lifeTick（约 757~824 行）里 life.tick 拿到 sendToOwner 闭包（约 817 行 `sendToOwner: (text) => this._sendToOwnerPeer(cfg.ownerPeerId, text)`），主动消息的发送通道是现成的。
- life.js tick 内的日常分享段（约 344~383 行）已经是事件驱动 + 冷却：流水事件窗口 `if (cur < at || cur > at + 35) continue;`（约 359 行）、冷却 `const coolMin = 60 + this._jitterFor('cool' + s.pokes, now, 30);`（约 351 行）、当天掷骰 `const roll = this._unitFor('say' + i, now);`（约 360 行）、只防连发不配额（注释写明"只是天花板，不再是配额"）。
- life.js tick 开头的睡眠硬闸（约 282~288 行）：

      if (this.isAsleepNow(now, cfg)) {
        ...
        skip('all', '她已经睡了（' + String(cfg.sleep || '') + ' 睡 / ' + String(cfg.wake || '') + ' 起）——睡着不打扰');
        this._save(s);
        return sent;
      }

  「她在睡觉就推到早上」可以直接复用 isAsleepNow（约 186 行，含按作息时间表兜底），不必新写睡眠判断。

- 主动消息的生成入口 soul.proactive（约 1328 行）是按 kind 分任务模板的（tasks 表约 1348~1359 行：morning/night/poke/nudge），并已带上【此刻】时间、今天的分寸、最近聊天记录（约 1289 行 hist 取最近 12 条）与"绝对不要自我介绍"铁律（约 1365 行）。加一个 promise 种类即可复用全部护栏。

1.3 队列不能放 life-state.json。life.js tick 每天跨日重置状态（约 266~275 行）：

    if (s.date !== dayKey(now)) {
      s.date = dayKey(now); s.morning = false; s.night = false; s.pokes = 0; s.nudges = 0;
      ...
    }

承诺队列必须跨天存活，所以独立文件；冷却语义也不能直接套 60±30 分钟——承诺是"到点必须说话"，不是"今天想不想说"，它要的是碰撞保护而不是冲动门。

1.4 发送通道有一个现实约束。index.js _sendToOwnerPeer（约 826~840 行）：

    const contextToken = this.store.getContextToken(acct.account_id, peer);
    if (!contextToken) throw new Error('主人还没有给她发过消息（协议要求先有过来往才能主动推送）');

主人从没来过消息时主动发送会抛错。承诺提醒必须容忍这个错（记账重试），不能让心跳挂掉。

1.5 试聊也会走 recordConversation。index.js 约 2959 行 panel/soul-test 带 record:true 落库。承诺抽取若不做范围限制，试聊里编的"周末给你讲"会混进真队列。

## ② 方案

2.1 总体数据流

    回复发出（index.js _driveSoulOnce 末尾 recordConversation 的 .then 链，约 1198 行）
      → promises.maybeExtract({peerKey, isOwner, userText, herTexts})   // 火后不管，绝不阻塞回复
          → 仅 isOwner=true 才抽（普通联系人抽了也没人送，还白白花钱）
          → chatCompletion（cfg.chain.memory 顺位链，与发前自检同一个链，index.js 约 1164 行同款）
          → 产出 {add:[{text,kind,due,time}], cancel:[编号]} → 归一化 → 去重 → 写 promises.json
    60 秒心跳（index.js _lifeTick 末尾，life.tick 之后）
      → promises.tick({ now, isAsleep, wake, send })                    // 独立模块，不进 life.js
          → 到期 + 醒着 + 无碰撞 → soul.proactive('promise', {promise}) → send → status='sent'
          → 在睡 → deferUntil = 今天(或次日)起床时刻 + 确定性抖动 15~45 分钟
          → 发送失败（如还没 contextToken）→ attempts+1，保持 pending，下跳再试

2.2 抽什么字段。每次抽取消调一个便宜模型，输入 = 今天的日期时间 + 待兑现清单（最多 10 条的编号与内容，供反悔比对）+ 本轮对话（他 ≤800 字、她 ≤600 字，直接复用 recordConversation 已截断前的原文，二次截断）。输出只允许一个 JSON：

    {"add":[{"text":"她答应的具体内容（第一人称，40字内）","kind":"self或remind","due":"YYYY-MM-DD","time":"HH:MM或null"}],
     "cancel":["明确反悔的待兑现编号"]}

字段定义：

- text：承诺内容，她视角第一人称（"周末把那本书的读后感讲给他听"）。
- kind：self = 她答应做的事/给的东西；remind = 她答应到点提醒他的事（"明天提醒你带伞"）。
- due：绝对日期，必填。提示词里给足今天的日期与星期（同【此刻】的做法，soul.js 约 1094 行），要求模型换算成绝对日期；她说不清具体日子就不登记（规则写明"别猜"），那种话本来就该由记忆系统兜底。没有到期日的承诺不是提醒，是念想。
- cancel：只有当本轮对话明确表达"算了/不用了/不用提醒了"且能对上待兑现编号时才给，避免模型顺手感觉像就取消。

代码侧归一化（不许模型说的算）：

- due 必须匹配 /^\d{4}-\d{2}-\d{2}$/，time 匹配 /^\d{1,2}:\d{2}$/ 或空；
- dueTs = new Date(年,月-1,日,时||9,分||0) 本地时区（与 dayKey 同一套本地时间口径）；
- dueTs 早于 now - 60 分钟视为模型算错，丢弃该条并记一条 activity（"承诺抽取：日期算到了过去，已丢弃"），不擅自改到未来。

2.3 队列存哪。本地 JSON：companionDir/promises.json。理由：本仓所有持久化都是 JSON + 原子写（参照 world-engine.js _write，约 140 行 tmp+rename 模式）；承诺数量级是几十条，SQLite 是给十万行用的，引进一个新依赖违背减法。写法照抄 _write 的 tmp+rename，防半截写。

    {
      "version": 1,
      "items": [
        {"id":"p_ab12","text":"周末把那本书的读后感讲给他听","kind":"self",
         "due":"2026-09-20","time":null,"dueTs":1758388800000,
         "createdAt":1758100000000,"roundTs":1758099900000,"peerKey":"account:peer","isOwner":true,
         "quote":"那这本书的读后感我周末讲给你听呀","status":"pending",
         "sentAt":0,"deferUntil":0,"attempts":0,"dupCount":1,"cancelReason":""}
      ],
      "done": [],              // sent/cancelled/missed 的归档，最多留 30 条
      "lastSentAt": 0,         // 承诺提醒的碰撞保护用
      "lastExtractAt": 0, "lastExtractOk": true   // 抽取健康度，后台可见
    }

去重：新抽取的 text 去掉空白与标点后与 pending 里同文本比对，命中则旧条 dupCount+1、不新增；同 due 且文本前 12 字相同也判重。她连着三轮说"周末讲给你听"只留一条。

与记忆桶化的关系：promises.json 是到期职责的唯一权威；记忆条目上的 todo 字段不再承担任何到期职责（见 1.1 结论），两边不互相同步，避免"同一件事两个源"。

2.4 到期怎么触发。复用现有 60 秒心跳（index.js _lifeTimer，约 424 行），在 _lifeTick 里 life.tick 返回之后加一步 promises.tick()。不新建定时器的理由：一个进程里已有两个 interval（心跳与轮询锁，index.js 约 424 / 504 行），第三个没有收益；且 promises.tick 需要的输入（isAsleep、wake、send 闭包）_lifeTick 手上全有。

不并入 life.js tick 的理由：life-state.json 每天跨日重置（1.3 证据），承诺必须跨天；且 life.tick 的日常分享是"冲动门 + 冷却"，承诺是"到点履约"，塞在一起会让两套语义互相污染（比如承诺提醒被 poke 冷却挡掉，等于"答应了又不认账"）。独立模块、独立状态文件、共享心跳与发送通道。

promises.tick 每跳的判定表（按序）：

1. 没有待兑现 → 直接返回（零开销）。
2. 睡眠硬闸：life.isAsleepNow(now, {wake, sleep}) 为真 → 所有到期项设 deferUntil（见下）并返回，不发送。这是"她在睡觉就推到早上"的唯一实现，与生活系统共用同一把睡眠尺子（life.js isAsleepNow，约 186 行，含时间表兜底，不存在"没发晚安就永远醒着"的旧坑）。
3. deferUntil 规则：deferUntil = 今天起床时刻 + 15~45 分钟确定性抖动（抖动用 life.js _jitterFor 同款 hash(dayKey+id) 思路，在同一天内恒定，重启不变）；如果此刻已过起床时刻（比如她 8 点起、10 点才到期的承诺醒着却没发过），deferUntil = now + 3 分钟即可。深睡时段（23 点后的"到今晚之前"承诺）天然被硬闸覆盖。
4. 碰撞保护：now - max(lastSentAt, life-state.json 的 lastPokeAt（只读借用，不代写）) < 10 分钟 → 本跳跳过，3 分钟后再试。只防"两条消息挤在同分钟"，不引入配额。
5. 发送：soul.proactive('promise', { promise }) 生成 1~2 条 → 逐条 send（复用 life.tick 的 doSend 节奏：条间延迟封顶 4 秒，life.js 约 290~297 行同款）→ status='sent'、sentAt=now、写 activity（"[承诺] 到期提起：周末讲读后感"）。每条承诺只主动提一次——真人也不会一天催自己三遍。
6. 发送抛错（contextToken 未建立 / 通道故障）：attempts+1，保持 pending，记 activity；attempts 当日累计 ≥3 则当天不再试（防刷日志），次日清零。
7. 过期兜底：dueTs 已过 72 小时仍 pending（电脑三天没开）→ status='missed' 归档 + activity 说明，不再自动发；后台列表给"补提一次"按钮，想补再补。

每日上限：常量 MAX_REMINDERS_PER_DAY = 3（写死在模块顶部，不做后台旋钮），超出的顺延到次日，防极端情况下抽取器抽出一串同日承诺刷屏。

2.5 到期她怎么提。soul.proactive 的 tasks 表（约 1348~1359 行）加一个 promise 种类：

    promise: '你之前答应过他一件事：' + String(extra.promise.text)
      + '（' + 答应那天的日期 + '答应的，说好的日子是 ' + extra.promise.due + '）。'
      + '现在到了该提起或兑现的时候。像突然想起来那样自然地说，1~2 句；'
      + '如果日子已经拖过了，先小小认个错再补上；绝不提"系统/队列/记录"这类词。'

proactive 现有护栏全部自动生效：【此刻】时间、今天的分寸、最近 12 条聊天记录（约 1289 行）、不自我介绍铁律（约 1365 行）、按性格的拆条与延迟。kind='remind' 与 'self' 的差别只体现在文案口吻（remind 更像"诶你别忘了带伞"，self 更像"说好的，故事来了"），在 extra.promise.kind 里带给模型，由模板一句话区分，不新增第二条链路。

2.6 后台哪里能看（禁黑盒）。后台「你们」页（console.html tRelation，约 212 行，SECS 列表约 214~218 行）新增折叠区 rel-promise「她答应过的事」：

- 列表列：内容 / 类型（她要做的 / 提醒你的）/ 答应时间 / 到期 / 状态（待兑现 · 已提起 · 已取消 · 已过期）/ 重复次数；
- 每条操作：取消（填一句原因，写进 cancelReason）/ 改期 / 补提一次（missed 或 sent 都可用，再发一条）；
- 顶部一行说明数据从哪来："每轮聊天后自动登记，她在睡觉会推到起床后；抽错可直接取消"；
- 抽取健康度一行：最近一次抽取时间与结果（ok / 失败原因 / 没配抽取模型），照「世界」页展示天气错误的做法（world-state.weatherError 已有先例）。

新增后台接口三个（index.js panel 路由区，约 2365 行起）：

- GET  panel/promises → {items, done, lastExtractAt, lastExtractOk, extractNote}
- POST panel/promises/action {id, op:'cancel'|'reschedule'|'remind', due?, reason?} → 逐项校验后改 promises.json，写 activity
- POST panel/promises/test {dialogue} → 用同一条链跑一次抽取但不入队（返回"会登记成什么"），后台调试用，防"抽没抽到"变黑盒

2.7 抽错/反悔怎么取消。三层：

1. 自动：2.2 的 cancel 字段——每轮抽取都把待兑现清单带给模型，本轮她明确反悔就按编号取消，cancelReason 记"她自己反悔（原话：算了不用了）"。
2. 手动：后台取消/改期（2.6）。
3. 失效：72 小时未兑现自动 missed（2.4 第 7 条），不赖在队列里。

2.8 成本控制。抽取用 cfg.chain.memory 顺位链（index.js 约 1164 行自检同款、约 877 行记忆提炼同款），逐槽回落，超时 12 秒，temperature 0，maxTokens 220。

- 单次调用量级：输入约 900 token（对话 1400 字截断 + 清单 + 指令），输出约 80 token。按主流低价档模型每百万 token 1~3 元的价位折算，一次约 0.001~0.003 元。
- 触发面：只在主人（isOwner）的每轮回复后跑一次；试聊与普通联系人不跑（2.1）。一天 100 轮封顶约 0.1~0.3 元/天，量级与现有每轮记忆提炼（mem0 云端模型，同一量级调用）持平。
- 失败不重试：解析失败/超时记 lastExtractOk=false 后直接放弃本轮，等下一轮；没有重试风暴。没配 chain.memory 时整条链路静默停用并在后台写明原因，不报错刷屏。
- 这套成本结构与"每轮用便宜模型抽取"的既定设计一致；若日后想再省，唯一的合法闸门是给 chain.memory 配更便宜的槽，而不是在链路里加开关。

## ⑤ 风险

1. 世界引擎把 body 写歪（塞故事/塞日期）。缓解：sleep 白名单四选一、ailment 截 16 字、note 截 40 字、forDate 强制引擎自己的值；提示词闸门 + 发前自检双网（2.9/2.11）；最坏情况退化为"一句无害的口语"，进不了任何数值。
2. 经期设计显得机械或冒犯。缓解：生理期只是电量与文案的一个输入，档位文案全部口语且程度轻；平稳期完全无感（一个月大多数天她没有"身体戏"）；整条链默认开但可关（用户已拍板默认开）。
3. 披露越界（刚认识就说破生理期）。缓解：档位由 intimacy 单源决定、阈值写死；闸门句直接给出各档的说话上限；自检层兜底。
4. "身体差=心情差"的同源污染。缓解：身体字段不写 mood、不写 deform 压力，只在 battery/traitDrift 生效；提示词明写"不是心情变坏"；分寸（intimacy/forbid）照旧由世界引擎独立判定。
5. 三处消费方各自解读导致漂移（本项目重点病）。缓解：所有身体事实与档位由 body-state.js 的 bodyView/bodyPromptLine 单点派生，daily/soul/console 只调用不复制逻辑；测试含单写者 grep 守卫（3.16）。
6. 引擎停摆或 JSON 坏档。缓解：world.body 缺失时视图降级显示"引擎未跑"，生理期照算；body-state.json 读失败按未建档重建（salt 重生成会换相位——写明这一行为：坏档等于重新建档，代价是周期相位重排，不影响其他系统）。
