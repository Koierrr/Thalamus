## 七、工程坑清单（血泪）

1. **组合页签的子函数禁止 `box.innerHTML=''`**——谁最后结束谁擦掉别人（机务页曾被整页清空，竞态偶发）。
2. **`_sanitizeConfig` 是白名单**：新增配置组不登记就被静默丢弃（曾丢过 embed.baseURL、world.weatherReal、memory.selfMemory、deform.*）。
3. **`_behavior()` 也是白名单函数**：曾把整个 `memory` 组丢掉 → 设置静默失效。
4. **领域关键字段名不匹配**：`info.deformLine` vs 传入的 `deformInfo`（变形曾完全没生效）。
5. **时序**：恢复/道歉指令必须在生成回复"之前"消费，否则永远赶不上那一轮。
6. **注释没闭合会吞掉后面一整段代码**（新增）：`/*` 少一个 `*/`，emoji 与手滑两个滑杆被一起吞进注释，页面上直接消失、还不报错。**改注释后一定要真渲染或跑 console-smoke。**
7. **`display:none` 包裹会造成"按钮看得见、输入框看不见"**（新增）：女娲 API 的 BaseURL/API Key 被包在隐藏 div 里，而按钮照旧读它们 → 用户永远填不了。删控件要连引用一起删，别用隐藏顶替。
8. **"能保存≠生效"的黑盒三连**（新增，第三次改版修的全部是这类）：①向量接口读的是**早就不存在**的 `cfg.ollama` → 后台填什么都不生效 ②「专属昵称」只在**已删除的**关系阶段跃迁时才进提示词 → 填了等于没填 ③「向量来源」下拉在元组第 3 位、判定位却写在第 3 位以外 → 从未渲染。**新增设置项时必须 grep 出真正的消费点，找不到就是没生效。**
9. **预览窗口尺寸**：`force-device-scale-factor` 会让 CSS 视口缩水（曾只有 952px，截图看不清、只排 2 列）；现用 1560×1180、scale=1。
10. **shell/转义**：大段 JS/CSS 用 `write` 工具写文件再拼接；heredoc 里 `\n`/`\d` 易被吃（**本批又踩两次**，其中一次把 JS 字符串拆成两行直接语法错误）；Edit 工具锚点要唯一。**补丁脚本一律用 `write` 写文件再跑，不要塞进 heredoc。**
11. 工作区改名会让 pnpm 软链全断（`Cannot find package 'silk-wasm'`）；vendored 四件套已实体化。
12. **局部变量遮蔽模块/工具名**（同一类坑踩了三次）：处理函数里的 `path` 遮蔽 node:path（控制台永远伺服旧页面）、tab 函数里的 `bar`/`card` 遮蔽控制台小工具、`var f=` 遮蔽字段助手。守卫：console-smoke 的"禁止覆盖全局工具名" + boot-smoke 的"处理函数内禁用 path 模块"。
13. **`let` 声明晚于使用**（TDZ）：`interestLog`/`relLine`/`today` 在 `out = {...}` 之后才声明 → `Cannot access X before initialization`。新增字段时先声明再组装。
14. **`loadCfg()` 返回的是配置对象本身**，不是 `{config:{...}}` → 记忆页写成 `rs[1].config` 后永远取到空对象。经验：保存后要把**后端回传的值写回输入框**，让"保存成功"看得见。
15. **删文件/写文件必须保持原形状**：重置把 `memory.json` 写成裸数组 → 每次回话都在 `mem.entries.filter` 上抛错。读取端一律加形状容错。
16. **行为变更要同步改断言**：手滑行为改成"不再说打错了"后，旧断言（找"啊打错了"）立刻变红。
17. **时间窗不能只比大小**：`if (现在 >= 目标时刻) 就发` 会在下午补发早安/晚安；跨天窗口要用绝对时间戳判断（`absWindowPhase`）。
18. **测试进程跑完全绿却不退出 = "烟测卡死"**（新增）：7 个测试文件拉起定时器/向量预热，事件循环不空，Node 一直挂着；用 for 循环串跑时任何一个挂住就拖死整轮。已修：这些文件末尾补 `process.exit(0)`，并新增 `run-all.mjs`（一测一子进程 + 硬超时 SIGKILL）。**推论：`EXIT=124` 就是"它没自己退出"，不是"结果不对"。**
19. **`innerText` 拿不到收起 `<details>` 里的字**（新增）：用 innerText 做"这段文字在不在页面上"的检查时，必须先把 `details` 全部 `open=true`，否则会把"折叠"误判成"缺失"。
20. **「前端生成的标签」和「筛选比较的字段」必须同源**（新增）：记忆分类的芯片按旧字段 `e.who` 生成「通用/她自己的话」，而筛选比的是新分类名——**两边永远对不上，点任何分类都筛不出东西**（用户报的「记忆分类不生效」）。凡「生成标签 + 按标签过滤」的地方，必须用同一个字段。

## 十一、世界引擎联动地图（她为什么"像个活人"）

世界引擎 = 每晚她睡着后跑一次的"命运编剧"。它只有**一个入口**（`world-engine.js#generate`）、**一个当前状态文件**（`world-state.json`，只存最近一晚）、**一个历史档案目录**（`diary/<日期>.md`，一天一份）、**一条铁律**（必须独立 API，不与对话接口共用、不回落）。

### 输入（喂进去什么）

| 来源 | 具体内容 |
|---|---|
| 人设 | 名字/职业名+职业类型/城市/年龄/背景/MBTI |
| 六维 | 当前六维（含当天浮动）→ 决定她"怎么反应" |
| 兴趣 | `persona.interests` → 决定痴迷话题的候选 |
| 昨天 | 昨天剧本里的长线小心思、她对主人的印象、社交圈编制 |
| 今天 | 今天的作息/事件（含"今天是上班"）/有没有熬夜 → 明天的作息要跟今天对得上 |
| 记忆 | 最近 12 条记忆（她的世界要跟你们聊过的事自洽） |
| 天气 | 真实天气（Open-Meteo，城市→坐标缓存；开关可关） |
| 工作 | 职业类型 + 是否工作日 + 强度 → 工作日必须有一件工作的事，并给 workload |
| 周结算 | 满 7 天才带：这一周被哄/被怼/聊天轮数 |

### 输出（各自去哪）

| 产出 | 落地到哪 | 谁消费 |
|---|---|---|
| 私人日记 | `world-state.json#diary` + **`diary/<日期>.md` 留档** | 「世界→她的日记」月历回看；也进她的记忆 |
| 明日作息 wake/sleep | 次日 `daily-state.json`（`worldAuthored=true`） | 主动消息时窗、回复速度、首页 🌍 |
| **作息基准 rhythm** | `world-state.json#tone.rhythm` | `daily.js` 覆盖后台手改并留痕（「世界→上帝视角」显示） |
| 心情基线 mood | 次日 daily mood | 六维当日漂移、说话温度；聊天里按天播种到关系心情 |
| 痴迷话题 focus | 次日 daily focus | 聊天提示词「今日痴迷」 |
| 生活流水 flow | 世界状态 + 进她的记忆（source=life） | 聊天（她会自然地提到今天干了什么） |
| 心里念头 thoughts | 世界状态 | 聊天提示词（气氛合适时冒出来） |
| 小秘密 secrets | 世界状态 | 聊天提示词（15% 概率、只在主人面前漏一点） |
| 社交圈 npc | 世界状态 `npcs`（编制 ≤6，按名字合并） | 聊天提示词 + 后台可见 |
| 长线小心思 longline | 世界状态 `longterm`（最多留 5 条） | 聊天提示词（慢慢推进） |
| 她眼中的你 portrait | 世界状态 | 聊天提示词「她对你的印象」；**后台只读** |
| 明天天气 | 世界状态（真实 API 优先，失败她编） | 心情/穿搭/关心话题 |
| **状态一句话 statusLine** | `tone.statusLine` | 「她的状态」第一行 + 聊天提示词 |
| **今晚是否失眠 insomnia** | `tone.insomnia` | 当晚入睡时长（15~45 分 vs 60~120 分） |
| **明天要不要主动 proactive/proactiveAt** | `tone.proactive` / `tone.proactiveAt` | `life.js` 的主动消息上限与时间窗（±90 分钟收窄） |
| workload（工作负荷） | 世界状态 | 职业机制：≥50 → 压力 + 当天六维 |
| 周结算 evolve | `persona.traits`（钳制 ±25 内）+ 成长理由进记忆 | 六维长期演化 |

### 联动方向（谁影响谁，一句话）

- **世界引擎 → 她的生活**：作息/心情/痴迷/流水/念头/秘密/圈子/长线/印象/分寸/主动倾向，全部经提示词或次日 daily 状态影响她的言行。
- **世界引擎 → 记忆**：流水与成长理由写进记忆（`source=life`），所以她"记得自己昨天干了什么"。
- **世界引擎 → 变形机**：只有 workload 这一条（工作负荷≥50 才触发），其余情绪不直接改压力。
- **她 → 世界引擎**：今天的作息/事件、六维、你们的聊天记忆、这周被哄/被怼的次数，都是编剧的素材。
- **性格 → 一切强度**：职业给场景，六维给反应强度（同一件事，不同性格不同后果）；压力阈值也由六维推。
- **她不知道自己是被"写"出来的**：提示词里明确要求"绝不提 AI/模型/生成"。

### 已知的"乱"与缓解

1. **两套作息来源**：世界引擎排了作息就优先（`worldAuthored`），职业机制只在她没剧本时改作息——已在后台写明"世界引擎优先"并留痕。
2. **世界引擎只跑过一晚**（且是旧版字段）：机制就绪、数据已有一份，但"周结算/新字段/日记月历"都还没在真实运行里验证过——重启后第一件事就是点一次「立刻生成一次世界」。
3. **秘密/念头这类"氛围素材"用概率注入**（秘密 15%），不是每次都出现——刻意的（否则她像在念剧本），排查时别误以为没生效；「上帝视角」能直接看到原始数据。
